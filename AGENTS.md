# AGENTS.md

logmoji is a small npm package: a console logger for Node.js scripts and services that prefixes each line with an emoji and supports levels, colors, timestamps and context loggers.

## Verify a change

CI (`.github/workflows/ci.yml`) uses pnpm 11 on Node 22 and runs:

- `pnpm install --frozen-lockfile`
- `pnpm test` (Jest, `src/tests/`)
- `pnpm types`
- `pnpm docs:build`

## Gotchas

- The code is CommonJS in `src/index.js`. `src/index.mjs` only re-exports it through `createRequire`, so make changes in `index.js`.
- `types/` is generated by `pnpm types` (tsc reads the JSDoc in `src/`) and is committed. After changing JSDoc or options, run it and commit the result. The publish workflow does not regenerate it, so npm ships whatever is committed.
- tsc never deletes stale output: `types/utils/get-date-log.d.ts` has no source file left.
- `docs/.vitepress/cache` is committed. The build leaves it alone, but the VitePress dev server rewrites it, so keep those changes out of commits.
- The docs home hero in `docs/index.md` shows version 1.0.6 while the package is at 1.3.0. Releases do not update it.
- CI pins pnpm 11 through `pnpm/action-setup` and package.json has no `packageManager` field. Overrides and allowed builds live in `pnpm-workspace.yaml`.
- Publishing runs when a GitHub release is created: `pnpm install --frozen-lockfile && pnpm test`, then `pnpm publish` with the `NPM_TOKEN` secret.

## Docs site

- VitePress source lives in `docs/`, with the config in `docs/.vitepress/config.mts` and base `/logmoji/`. It is served at https://halitsever.github.io/logmoji/ with `.html` page URLs.
- `.github/workflows/docs.yaml` deploys on every push to `main`.
- A new page needs a `description` line in its frontmatter, a sidebar entry in the config and a line in `docs/public/llms.txt`. The sitemap, canonical and `og:url` tags are generated.

## Conventions

- Commit messages are a conventional-commit subject line in English, with no body and no trailer.
- Work on a branch and open a PR against `main`. The owner merges.
- New text carries no emoji. Code comments stay short, one line where possible, and explain why.
- The README follows the owner's template. Every image served from `halitsever-api.vercel.app` stays byte-for-byte. Only the `title=` value of `api/repo-title` and the link around `api/issue` may be corrected.
- The owner bumps versions (bare `1.3.0`-style commits) and publishes to npm.
